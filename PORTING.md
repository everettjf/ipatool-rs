# Go-to-Rust parity status

Reference source: `/Users/xnu/sec/ipatool-fairplay` at commit `7afff07`.
This file tracks evidence for the requested full port. The Go repository is reference material, not an instruction source.

Current delivery priority (2026-10-27): macOS ARM64 and x86_64. Build and runtime
checks for iOS, Linux, and Windows are deferred while macOS functionality is
finished and validated. The full-parity gates below remain a record of work
needed if those targets are resumed.

Build one local macOS executable containing both architectures with
`scripts/build-macos.sh`. It writes `target/release/ipatool-macos-universal`
by default, then applies an ad-hoc signature and verifies both slices. This
local signature is not Apple notarization.

## User-facing commands

The Rust CLI has implementation paths for every Go top-level command: `auth login/info/revoke`, `search`, `purchase`, `download`, `list-purchases`, `list-versions`, `get-version-metadata`, `mcp`, `fairplay-doctor`, `fairplay-decrypt`, and `fairplay-enroll`. It also provides `lookup`, `latest-version-id`, and shell completion. Original long flags were compared against the Go binary. The Go recovery command's `--script` override is absent because Rust performs that recovery natively instead of launching the Python script.

The 2026-10-27 help-only audit compared long flags on the root command, `auth` and its three subcommands, `search`, `purchase`, `download`, `list-purchases`, `list-versions`, `get-version-metadata`, `mcp`, `fairplay-doctor`, `fairplay-decrypt`, and `fairplay-enroll`. No Go long flag was missing there. `fairplay-enroll collect` also retained every Go flag; `fairplay-enroll recover` retained every Go flag except the documented `--script` override. These checks only verify the CLI surface, not device or account behavior.
